# ADR 0013：工作流新建即启用，用停用代替草稿审核门

- 状态：已采纳（2026-11-12）
- 影响面：workflows 的存储初始化、保存工具、页面状态展示、旧草稿迁移、文档

## 背景

v4 保存工作流时默认写成 `draft`，必须由人在页面激活后才能启动作业。于是页面长期存在「激活」这个概念：工作流明明已经创建，却还不能用。实际使用中，起草与保存由编排会话完成，人工激活只是额外一次点击；用户真正需要的是「暂时不用某个工作流时把它收起来」。

## 决定

1. **新建即启用**：`buka_workflow_save` 保存的新工作流直接是 `active`，保存后即可启动作业。
2. **只保留停用 / 重新启用**：页面不再出现「激活」或「草稿」。停用的工作流不能新建作业，已有作业继续运行，定义与历史只读；重新启用后恢复。
3. **旧草稿一次性归一**：存储初始化时把遗留的 `draft` 更新为 `active`，之后不再写入 `draft`。`retired` 保留，含义是「已停用」。
4. **列表降噪**：停用的工作流留在列表里，灰显并排在后面。

## 后果

- 取消人工审核门：编排 agent 保存的定义立刻可运行，页面审阅从「必经门」变成「建议动作」。
- 历史工作流不需要逐个重新激活；升级后直接可用。
- 与 ADR 0006「页面审阅工作流」不冲突：审阅仍然存在，只是不再阻塞启动作业。
- 工具文案、DETAIL、README、页面状态标签都要同步；`test/workflows-core.test.mjs` 增加旧草稿归一断言。
