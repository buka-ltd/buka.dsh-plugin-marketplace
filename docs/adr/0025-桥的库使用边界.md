# ADR 0025：桥的库使用边界

- 状态：已采纳（2026-11-18）
- 影响面：Skills 插件的发现 / 已安装列表、安装与卸载、检查与更新，以及 `skills` 依赖的升级路径

## 背景

#10 要求 Skills 插件收口到 `skills` 包：安装 / 卸载用库 API，检查 / 更新用包自带 CLI，不再 spawn `npx`。这部分已经落地。但同一个 issue 里「发现、安装、列表、卸载改用库 API」的表述也覆盖了发现与「已安装」列表，而这两块的事实来源比 `skills` 包能看到的更宽：

- 收藏仓库的扫描只认仓库根 `skills/` 下的目录（允许任意层级），远端来源还要先浅克隆到本地缓存；
- 「已安装」除了 `skills-lock.json` 管理的条目，还要列出两个全局根（`<DSH_HOME>/skills`、`<DSH_AGENTS_HOME>/skills`）里手工放进去的 skill；
- 仓库内容有持久缓存与 TTL：刷新失败时保留旧克隆，离线也能读出上次的列表。

`skills` 包的 `installSkills` / `removeSkills` 与 lock 只覆盖「由它安装、且记录了来源」的条目；它没有「扫描一个任意目录并当作可安装来源」的公开入口，也不认识插件自己的克隆缓存与两个全局根的手工条目。

## 决定

1. **执行层用库**：安装走 `installSkills`，卸载走 `removeSkills`，检查 / 更新走 `skills` 包自带的 CLI；安装时把**原始来源**（GitHub 简写 / git URL / 本地路径）交给库，保证 lock 里的来源仍可再解析；调用 CLI 时关闭遥测。运行时不再 spawn `npx`。
2. **发现与列表仍由插件扫描**：只认仓库根 `skills/` 下的 skill；发现与「已安装」由 `src/repo-skills.ts`、`src/local-source.ts`、`src/skill-store.ts` 自己读本地浅克隆缓存、两个全局根与目标目录，不依赖库的列表 API。
3. **两边用 lock 与来源字符串衔接**：列表里由 `skills-lock.json` 管理的条目带来源、参与检查 / 更新；手工条目只展示、允许本地删除，不参与检查 / 更新。
4. **状态由库语义决定**：检查结果只使用 `update` / `modified` / `up-to-date` / `unsupported-source` / `failed`；旧 Claude marketplace 安装解析不出仓库根 `skills/` 来源，标为 `unsupported-source`，不误报为「已是最新」。

这是一项**已接受的规格偏差**：#10 的「发现、列表改用库 API」只在执行层成立，读取层保留插件自己的扫描。

## 后果

- 手工放在全局根的 skill、旧 marketplace 安装、刷新失败时的离线缓存仍然可见；这是保留扫描层换来的能力。
- 这些条目的来源与版本状态不由 `skills` 包维护：手工条目没有 lock 记录，不能检查 / 更新；旧 marketplace 安装只能标记为不支持的来源。
- 插件要自己维护扫描、来源归一化、克隆缓存与 lock 解析（`src/repo-skills.ts`、`src/local-source.ts`、`src/git-source.ts`、`src/skill-store.ts`、`src/npx-lock.ts`）；`skills` 包升级时这些模块与 `test/repo-skills.test.mjs`、`test/skills-update.test.mjs` 要一起复核。
- 发现与列表之间存在两套真相：库知道「自己装了什么」，插件知道「磁盘上有什么」。两者冲突时以磁盘与 lock 的合并结果为准，页面不伪造版本号。

## 将来的迁移路径

如果 `skills` 包将来提供以下任一能力，读取层可以逐步退化：

- 一个能扫描任意根目录、不要求条目出现在 lock 里的列表 / 来源 API；
- 允许传入自定义全局根与缓存目录的 `listSkills` / `resolveSource`；
- 能返回来源是否可解析、而不只返回 lock 条目的检查接口。

迁移时按下面的顺序，不预埋分支：

1. 先把 `repo-skills.ts` 的仓库扫描换成库的列表 API，保留插件自己的克隆缓存与 TTL；
2. 再把 `skill-store.ts` 的全局根合并交给库，手工条目改为「库列出 + 无 lock 来源」；
3. 最后评估是否删除 `local-source.ts` 与 `git-source.ts`。只要库仍不支持自定义根与离线缓存，这两步就不做。

在此之前，本 ADR 的边界就是当前实现：**执行用库，读取用插件**。
