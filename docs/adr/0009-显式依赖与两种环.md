# ADR 0009：显式依赖、两种环、没有批次

- 状态：已采纳（2026-11-12）
- 影响面：任务模型、创建校验、调度、看板

## 背景

旧模型有 join 屏障与「一批任务」的隐含语义；用户明确反对批次设计：任务可以随时添加，不需要节点结束才成批产出。同时真实流程需要「测试失败打回研发」。

## 决定

1. **任务依赖纯显式。** 任务条件 = 它声明的依赖；没有自动父依赖；可以依赖已创建但未完成的任务，不能依赖尚未创建的任务。
2. **依赖引用范围 = 本作业内任意已创建任务。** 引擎只校验存在、同作业、不是自己、依赖图无环；执行中的任务可只读整个作业看板以便跨分支引用。
3. **两种环分开。** 工作流图可以成环（显式 `back` 回边 + 预算）；任务依赖图永远无环，因为依赖只指向更早创建的任务。每次打回产生新任务记录。
4. **任务类型可声明 `requires`。** 创建时校验依赖集合里至少有指定类型的任务；只校验，不绑定、不注入等待。
5. **批次 / 代次 / 节点屏障全部废除。** 任务集合只是描述，不是等待单位；唯一的结构性依赖是 `start.next` 模板里显式的 `"$start"`。

## 后果

- 引擎不需要 batch / generation / join 算法，复杂度显著下降。
- 打回、返工、循环都用「新任务记录 + 回边」表达；预算必须存在。
- 创建任务时的校验成为风险边界的一部分。
