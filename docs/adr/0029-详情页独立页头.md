# ADR 0029：详情页使用独立页头，首页页签只留在列表页

- 状态：已采纳（2026-11-19）；修订 ADR 0027 的页面布局部分
- 影响面：`plugins/workflows/src/client`（`home.ts`、工作流页头、执行者页头、样式）、`test/workflows-client.test.mjs`、`test/workers-client.test.mjs`、插件 README 与 DETAIL

## 背景

ADR 0027 把两个页面合并成一个入口后，首页顶部的「工作流 / 执行者」页签由 `home.ts` 生成并交给两个页面，放进每一屏的页签带。列表页因此不再需要自己的大标题，页签本身就是标题；但详情页也跟着保留了这层页签，页面变成：

```
[工作流 | 执行者]                        [新建作业] [刷新] [更多]
← 研发交付  v3
[作业 | 结构图]
```

工作流详情、作业详情和执行者详情都是「进入了一层」的页面，顶部却仍压着入口层的切换器，与页内自己的页签形成两排页签；详情页的动作按钮也被放在入口层那一行，与标题分离。这个布局读起来像「首页里嵌了一个子页面」，而不是一个独立页面。

## 决定

1. **首页页签只出现在两个列表页**：工作流列表、执行者列表保留「工作流 / 执行者」页签，页签仍是这一屏的标题，操作按钮在同一行右侧。`home.ts` 继续生成页签并按 hash 切换页面，是否渲染页签由页面按当前视图决定。
2. **详情页用独立页头**：工作流详情、作业详情、执行者详情不再渲染首页页签，页头改为两行——第一行是「返回 + 标题 + 状态 / 元信息 + 操作按钮」，第二行是页内页签（作业 / 结构图，概览 / 实时流程 / 看板 / 资产，设置 / 文件 / 技能）。返回按钮是回到上一层的唯一入口。
3. **路由与页签状态不变**：`#/workers` 仍落在执行者页签，其余 hash 仍是工作流路由；页面卸载 / 重新挂载的规则与 ADR 0027 相同。删除执行者影响面弹窗里的「打开作业」仍只写 `#/job/...`，首页监听 hash 后自动切回工作流页签并打开作业。
4. **样式跟随结构**：详情页页头仍吸顶；标题行允许换行，操作按钮始终靠右；页内页签单独占一行并左对齐。列表页的页头结构不变。

## 后果

- 详情页少了入口层页签，标题与操作回到同一视线；页内页签不再和首页页签上下叠两排。
- 从详情页切到另一个入口层页签需要先返回列表（或使用已有的跨页跳转，如「打开作业」）；这是详情页「独立页面」定位的代价。
- `home.ts` 与两个页面之间的契约不变（仍传 `topTabs`），只是页面只在列表视图使用它；后续若再加一级详情，沿用同样的页头结构。
- 测试从「详情页也带首页页签」改为断言详情页没有首页页签、但有页内页签。
