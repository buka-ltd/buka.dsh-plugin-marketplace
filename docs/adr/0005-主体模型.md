# ADR 0005：执行者是主体，机器人分 agent / program 两种

- 状态：已采纳（2026-11-12）
- 影响面：`plugins/workflows`、`plugins/robots` 的执行者模型、`robots.json`、任务调度

## 背景

旧模型把执行者拆成 `robot` 与 `user` 两种节点，工具（例如时钟）没有归属；需要「等到某时刻」时只能在引擎里加一个系统层，或者把它硬塞进机器人节点。实际需要的是任意能独立处理任务的对象。

## 决定

1. **执行者是主体。** 主体分两种：人、机器人。
2. **机器人分两种驱动。**
   - agent 型：DSH 会话，拥有目录、AGENTS.md、项目 skills；由 `robots` 插件登记。
   - program 型：固定程序，接收输入 → 产出输出；例如 `clock`。
3. **工具是 program 机器人，不是系统层。** 时钟、定时器、未来的 HTTP 调用，都按机器人登记与调度。
4. **`robots.json` 升级到 version 2**：新增 `driver: "agent" | "program"` 与 `assistant: boolean`；旧条目迁移补 `driver: "agent"`、`assistant: false`。
5. **v1 的 program 机器人只有内建 `clock`**：不可创建、不可删除；登记与展示在 robots 插件，执行实现由 workflows 插件注册。未来再开放用户自定义 program 机器人。
6. **启动者是参与者。** 开始 / 结束任务的执行者是启动者：人（页面启动）或会话（`/job` 启动），不要求是登记机器人。

## 后果

- 「机器人」不再等价于「有目录的 agent」；robots 页面要区分 driver，program 机器人只读。
- 工作流的 `executor` 写 `{ kind: "robot", name }` 或 `{ kind: "human" }`；`name` 解析到 agent 或 program 机器人。
- 任务的执行者、承办者、启动者三者要分开记录。
- 旧 `user` 节点、`system` 执行者的概念删除。
