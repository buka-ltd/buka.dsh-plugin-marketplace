# ADR 0008：内建开始 / 结束节点与启动者

- 状态：已采纳（2026-11-12）
- 影响面：工作流定义、作业创建、作业结算、`/job` 命令

## 背景

旧模型的 `start` / `end` 只是流程标记；没有人负责「谁发起这次工作、结果回到谁」。用户要求开始与结束是明确出入口，谁开始谁处理结束；启动者本身是参与者。

## 决定

1. **内建开始 / 结束节点。** 每个工作流恰有一个 `start` 与一个 `end`，不可删除；执行者都是启动者。
2. **启动者是参与者。** 人（页面启动）或会话（`/job` 启动）；不要求是登记机器人；记录在作业上。
3. **启动任务。** 作业创建时生成，payload = 原始输入，output = 第一个结构化输入。会话启动由该会话 agent 执行（一轮），人启动在页面同时填原始输入与结构化字段。启动任务完成后，引擎按 `start.next` 模板创建初始任务，模板必须显式依赖 `"$start"`。
4. **结束任务。** 由岗位沿 `岗位 → end` 的边派发，payload = 最终交付物，没有 output；**投递即完成**，不需要确认。会话启动者 resume 后投消息；人启动者在看板看到交付物。投递失败时任务停在待认领，作业保持 `running`，页面手动重试。
5. **结算。** 没有非终态任务后：至少一条结束任务完成且没有 failed / blocked → `completed`；有失败分支或没有结束任务完成 → `failed`；用户取消 → `cancelled`。

## 后果

- 作业编号、启动者、开始 / 结束任务要持久化。
- `/job` 命令成为普通会话的入口；页面启动 = 人启动者。
- 交付失败不能自动判失败，需要人工重试入口。
