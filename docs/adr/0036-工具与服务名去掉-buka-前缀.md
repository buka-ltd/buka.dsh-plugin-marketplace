# ADR 0036：工具、服务与页面命名去掉 buka 前缀

- 状态：已采纳（2026-11-25）；同日追加一轮：页面路由、面板 id、locale namespace、日志与 effect label、skill-update-check 插件一并调整
- 影响面：workflows / skills / bell / pen / skill-update-check 五个插件的工具、服务、页面路由、面板 id、locale namespace、日志与 effect label、插件 id；README / DETAIL / GLOSSARY / ADR 0035 的引用、测试与构建产物

## 背景

Workflows 与 Skills 两个插件的模型工具、Host Service 与注入上下文的消息来源长期带 `buka` 前缀：`buka_workers`、`buka_workflow_save`、`buka_job_start`、`ctx.bukaWorkers`、`ctx.bukaSkills`、`buka-worker`。前缀来自更早的插件包名，对模型和调用方没有信息量；同一类名字里还混着 `buka_` / `bukaWorkers` / `buka-worker` 三种写法。

用户要求统一整理：工具名不再以 `buka` 开头；workflow 相关的命名以 `workflow` 开头，例如注入上下文时使用 `workflow_worker`；对外服务与其他插件的工具一并调整。

## 决定

1. **Workflows 的模型工具改为 `workflow_*`：**

   | 旧 | 新 |
   | --- | --- |
   | `buka_workers` | `workflow_workers` |
   | `buka_worker_build` | `workflow_worker_build` |
   | `buka_workflow_save` | `workflow_save` |
   | `buka_workflow_list` | `workflow_list` |
   | `buka_workflow_get` | `workflow_get` |
   | `buka_job_workflows` | `workflow_job_options` |
   | `buka_job_start` | `workflow_job_start` |
   | `buka_job_status` | `workflow_job_status` |
   | `buka_job_cancel` | `workflow_job_cancel` |
   | `buka_job_board` | `workflow_job_board` |
   | `buka_job_attachments` | `workflow_job_attachments` |
   | `buka_task_create` | `workflow_task_create` |
   | `buka_task_complete` | `workflow_task_complete` |
   | `buka_task_get` | `workflow_task_get` |

   定义类工具去掉重复的 `workflow`（`buka_workflow_save` → `workflow_save`），而不是 `workflow_workflow_save`。作业模式的列表工具叫 `workflow_job_options`，避免 `workflow_job_workflows` 连写。

2. **Skills 的只读工具改为 `skill_list`。** 它列举本机全局 skills，不再带 `buka`，并与 DSH 的 `<domain>_list` 风格一致。

3. **对外服务去掉 `buka`，按领域命名：**
   - `ctx.bukaWorkers` → `ctx.workflowWorkers`（执行者登记与会话投递，skills 插件消费）；
   - `ctx.bukaWorkflows` → `ctx.workflowQuery`（工作流一半的只读查询服务，`workerUsage(id)`）；
   - `ctx.bukaSkills` → `ctx.skillCatalog`（skills 的仓库 / 技能目录服务，workflows 消费）。
   两个插件在同一轮里一起改，服务名与消费方保持同步。

4. **注入上下文的消息来源：** `buka-worker` → `workflow_worker`（`contextMessage()` 的 `source.kind`）。**系统提示词段落：** `buka-workflows:job-policy` → `workflow_job_policy`。

5. **不保留兼容别名。** 这些名字只在本仓库的两个插件、插件提示词与自动化脚本里出现；留别名会让 `buka` 前缀长期存活。旧会话日志里的 `buka-worker` 来源、旧工具名只是历史文本，不参与新调度。

6. **页面路由、面板 id、locale namespace、日志与 effect label 一并去 `buka`：**
   - workflows：路由 `/buka-workflows/*` → `/workflow/*`、`/buka-workers/*` → `/workflow/workers/*`；面板 id 与 locale namespace `workflow` / `workflow-workers`；Tab、面板与表单 id 用 `workflow-*` / `workflow-workers-*`；日志与 effect label 用 `workflow:` / `workflow-workers:`。
   - skills：路由 `/buka-skills/*` → `/skills/*`；面板 id 与 locale namespace `skills`；Tab / 面板 / 表单 id 用 `skills-*`；日志与 effect label 用 `skills:`。
   - bell：试听路由 `/bell/preview`；设置区块 id 与 locale namespace `bell`；日志与 effect label 用 `bell:`。
   - pen：状态 / 开关路由 `/pen/state`、`/pen/toggle`；插槽 id `pen` / `pen-mark`；locale namespace `pen`；日志与 effect label 用 `pen:`。
   - skill-update-check：插件 id / 补丁行 id `check-skill-update`；路由 `/skill-update-check/*`；locale namespace、徽标 id 与 CSS 类 `skill-update-check-*`；日志与 effect label 用 `skill-update-check:`。

7. **以下名字保持不变：**
   - 包名 `@buka/...`（组织命名空间）；
   - 存储域 `buka_workflow`（已持久化，改名需要迁移）；
   - 数据目录 `~/.cache/dsh-plugin-workers/`、`~/.cache/dsh-plugin-workflows/`、`~/.dsh/buka-skills/`（skills 的仓库与缓存）；
   - workflows / skills / bell / pen 的 CSS 类名 `.buka-*`（纯样式，未参与本轮命名）；
   - bell / pen / skills / workflows 的补丁行 id 与插件名（`sound-buka-bell`、`mcp-buka-pen`、`skill-buka-skills`、`tool-buka-workflows`），以及 bell 的配置命名空间 `sound-buka-bell`（已持久化的用户设置）；
   - 浏览器 localStorage 键 `dsh.buka-skills.*`（可重建的页面缓存）。

## 备选与否决理由

- **只改工具名，保留服务名。** 用户明确要求“对外服务和其他插件工具都调整”，服务名继续带 `buka` 会让两个插件之间的契约与工具面脱节。
- **机械把 `buka_` 替换成 `workflow_`。** 会得到 `workflow_workflow_save`、`workflow_workflow_list` 这类重复名字；定义类工具应只保留一个 `workflow`。
- **把 `buka_job_workflows` 改成 `workflow_job_workflows`。** 两个 `workflow` 连写，读起来像一个 workflow 对象的集合；`workflow_job_options` 更贴近“这次作业的可选项”。
- **连存储域一起改。** 存储域改名要迁移存量工作流 / 作业 / 任务，必须单独立项；路由与面板 id 已在同日的第二轮里调整。
- **保留 `buka_skills`。** 它正是“其他插件工具”的那一个；保留会让“不使用 buka 开头”只完成一半。

## 后果

- 所有引用旧工具名的提示词、文档与自动化脚本都要同步；本仓库内已全部更新，测试断言也改为新名字。
- 旧会话里的工具调用记录不会被重写；恢复旧任务时不需要旧工具名，新会话使用新名字。
- 服务注入方（skills 插件与 workflows 的执行者删除路由）必须同时升级；本仓库两个插件同版本发布，不存在混装。
- 页面路由、面板 id、locale namespace 与日志 label 不再带 `buka`；旧的浏览器本地状态（面板顺序、展开状态等）会因 id 变化而重置。CSS 类名、补丁行 id、存储域与数据目录仍带 `buka`，属于样式 / 组成 / 持久化层面，后续可各自独立处理。
- 构建产物 `plugins/*/lib` 需要重新生成并提交；测试钉住新工具名的可见性与说明。
