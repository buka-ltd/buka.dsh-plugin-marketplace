# ADR 0027：界面合并为单入口、首页双页签

- 状态：已采纳（2026-11-18）
- 影响面：`plugins/workflows/src/client`（注册、新增 `home.ts`、文案、样式）、`test/workflows-client.test.mjs`、`test/workers-client.test.mjs`、插件 README 与 DETAIL

## 背景

ADR 0026 把两个插件合并进一个包，界面仍保留两个侧边栏入口（`buka-workers` 与 `buka-workflows`），UX 与原有两个插件时一致。合并后两个页面同属一个插件、互相跳转（删除打工人的影响面弹窗里「打开作业」要先 `layout.selectPanel('buka-workflows')` 再写 hash），两个入口拆散了同一个产品的管理面，侧边栏也因此多占一格。

## 决定

1. **只保留一个侧边栏入口**，id 沿用 `buka-workflows`（兼容布局服务的面板选中、DSH 已持久化的面板状态），label 改为「工作流与打工人」/ "Workflows & Workers"。删除 `buka-workers` 的 `sidebar.panellist` 与 `main` 注册。
2. **入口首页顶部两个页签**，第一个 **Workflow**、第二个 **Worker**：新增 `src/client/home.ts` 的 `HomePage` 装配，页签下按激活状态只挂载 `WorkflowsPage` 或 `WorkersPage`（两页源码不动）。`main` 插槽的 `inject` 额外提供 `workersT`（`ctx.locale.bind('buka-workers')`），因为一个面板只有一个 `locale` 绑定的 `t`。
3. **页签由 hash 驱动**：`#/workers`（或 `#/workers/…`）落在 Worker 页签，其余 hash 都是工作流路由。`HomePage` 监听 `hashchange` 更新页签，并记住最后一次工作流 hash，切回 Workflow 页签时恢复（如作业页）。刷新、前进 / 后退保持页签。
4. **跨页签跳转只写 hash**：删除打工人影响面里的「打开作业」写 `#/job/...` 即可，`HomePage` 自动切回 Workflow 页签；原 `layout.selectPanel('buka-workflows')` 调用删除（点击时面板必已选中）。`#/workers` 对工作流路由解析器是未知 hash，安全回落到工作流列表。
5. **不保留未激活页签的状态**：切页签卸载另一页，打工人页的选中态 / 草稿丢失——与合并前两个面板互切的行为一致（面板切换本就卸载页面）；工作流页路由与数据在 hash 与 Host 里，重新挂载即恢复。不做「两页同时挂载、CSS 隐藏」：那会让隐藏页继续轮询，且图形视图在 `display:none` 下布局失真。

## 后果

- 侧边栏从两个入口变成一个；旧用户升级后 `buka-workers` 面板消失，其功能在 Worker 页签内，数据与路由不变。
- `buka-workers` 命名空间（NS）保留给打工人词典与 `/buka-workers/*` 路由，只是不再注册面板。
- 冒烟测试从「直接调页面组件」改为「调 `HomePage` 并停在目标页签」：状态队列首位注入页签值；`walk` 对函数组件的展开加一次性缓存，避免同一棵树被反复遍历时页面内部的 `useState` 再次消费队列。
- `WorkersPanelIcon`（`workers/avatar.ts`）与打工人 `PANEL_ID` 常量已删除：面板合并后无引用。
