# ADR 0014：术语更名为「打工人 / 智能体 / 机器人」，插件改为 Workers

- 状态：已采纳（2026-11-13）；取代 ADR 0005 的命名部分
- 影响面：`plugins/workers`（原 `plugins/robots`）、`plugins/workflows`、`plugins/skills`、市场索引、术语表、全部文档与测试

## 背景

旧术语里「机器人」既是**非人主体的总称**，又是其中一种驱动（program 型）；「agent 型 / program 型」是从 `driver` 直译来的分类名。三层意思叠在同一个词上：

- 说「机器人」时，读者不知道是指全部执行主体，还是指固定程序那一种；
- 智能体（DSH 会话）与固定程序（clock）在中文里没有各自的名字，只能带着英文分类词说话；
- 插件叫 `robots`，页面叫「机器人」，但 agent 型与 program 型都是「机器人」，配置页与只读页要靠 driver 区分。

## 决定

1. **总称改为「打工人」（worker）**：非人主体，只有两种：智能体、机器人。
2. **agent 型改称「智能体」（agent）**，代码取值 `driver: "agent"`；有目录、AGENTS.md、项目 skills，以 DSH 会话执行任务。
3. **program 型改称「机器人」（robot）**，代码取值 `driver: "robot"`；固定程序，接收输入 → 产出输出，不建会话（v1 只有内建 `clock`）。`program` 只保留为机器人的程序 id 字段。
4. **插件身份整体改名**：
   - `plugins/robots` → `plugins/workers`，包名 `@buka/dsh-plugin-robots` → `@buka/dsh-plugin-workers`；
   - 补丁行 `page-buka-robots` / `preset-robot-builder` → `page-buka-workers` / `preset-worker-builder`；
   - preset 显示名「机器人构建」→「打工人」，id `robot-builder` → `worker-builder`；
   - 路由 `/buka-robots/*` → `/buka-workers/*`，服务 `ctx.bukaRobots` → `ctx.bukaWorkers`；
   - 工具 `buka_robots` / `buka_robot_build` → `buka_workers` / `buka_worker_build`；
   - 缓存目录 `~/.cache/dsh-plugin-robots` → `~/.cache/dsh-plugin-workers`，目录 `robots/` → `workers/`，登记文件 `robots.json` → `workers.json`。
5. **登记表升到 version 3**：`driver` 取值 `program` → `robot`；读 v1 / v2 旧表时在内存里迁移，下一次写入落盘 v3。
6. **工作流协议跟着改名**：岗位执行者写 `{ kind: "worker", name }`，承办者 `kind` 取 `human` / `worker` / `assistant`；已存作业快照里的 `kind: "robot"` 与 `driver: "program"` 在存储初始化时归一。
7. **旧数据自动迁移**：默认布局启动时把旧缓存目录搬到新位置、把 `robots/` / `robots.json` 改名为 `workers/` / `workers.json`、平移登记表里的目录路径、把登记表升到 v3。自定义 `workersDir` 时只升级登记格式——插件不知道用户的旧目录在哪。

## 后果

- 旧包与新包是两个独立插件：新插件挂好后需要卸载旧插件；默认缓存里的打工人自动跟过来，旧会话日志按旧工作区路径留在历史里。
- 包名、路由、服务名、工具名、存储路径全部是破坏性变更，不保留旧名别名；跨插件调用方（workflows、skills）同步改到新名字。
- 中文与英文文案统一为 worker / agent / robot 三层；`driver`、`executor.kind`、市场关键词、README / DETAIL / GLOSSARY 与测试断言一起更新。
- 旧 ADR（0005 ~ 0013）保留当时的写法，作为历史记录；术语以本 ADR 与 `GLOSSARY.md` 为准。
