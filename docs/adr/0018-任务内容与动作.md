# ADR 0018：任务内容与动作

- 状态：已采纳（2026-11-14）
- 影响面：workflows 的定义格式、工具、引擎、页面、存储与演示工作流
- 取代：ADR 0010 的第 5 条、ADR 0017 的人任务部分与提示词段数

## 背景

v6 的人任务只能「认领 + 按 output schema 填表」，提交后不会创建任何任务；于是要让流程经过一个人工节点，只能由前一个任务**预创建**后继任务并让它依赖人任务。这个做法在三种情况下站不住：

- 人「拒绝」时，预创建的后继照样运行，因为引擎不读结果里的 `approved`；
- 一个岗位有两条出向通道时，预创建无法表达「这一次走哪条」；
- 预创建的后继被取消或失败，最后一个接手的人提交后没有接手者。

同时，v6 的任务类型有两套 schema：payload（创建者填）与 output（执行者交回）。output 唯一可能的消费者是模板，而 v6 的模板又要求作者写出运行时的任务 id，实际上没人能可靠地引用它。

## 决定

1. **任务 = 任务内容 + 结果。**
   - 任务内容由创建者写，按任务类型的 **content** schema 校验；可以是字符串，也可以是对象。
   - 结果只由执行者交回**一段总结文本 + 附件**，没有结构化契约；结果不进流程，只给管理作业的人看。流程的价值在任务创建的后继任务。
2. **任务类型 = 定义 + 内容 + 动作。**
   - `definition`：编排者预设的信息（这个任务类型是什么、外部系统的事实），执行者必读。
   - `content`：任务内容的格式约束。
   - `actions`：只属于人岗位，见下条。
   - 删除 `requires`：依赖只有实例级的 deps，时序由通道与 deps 表达。
   - 岗位只剩名字与可选备注，不再有指向执行者的说明文字。
3. **人的操作就是创建任务。** 人任务类型的每个动作声明名称、可选表单（input schema）与一组创建声明（通道 + 任务类型 + 内容模板）。点击即派发 = 没有表单的动作；一个动作可以创建多个任务，也可以一个都不建。拒绝、打回、双通道都由显式动作表达，预创建彻底删除。
4. **执行提示词只有三段**：工作流规则 / 任务类型的定义 / 任务内容。模板只在定义声明的创建里求值，可用 `{{content.*}}`（正在完成的任务的内容）与 `{{input.*}}`（动作表单）。
5. **开始节点与普通任务同构**：作业输入就是启动任务的内容，提交后由 `next` 创建初始任务；不再有「原始输入 → 结构化输入」的两步。
6. **结束任务要确认。** 结束任务的内容就是最终报告，按结束节点的 content schema 校验；交回方式由发起人在创建作业时选择（交回发起人，或交给助理代收）。会话发起时投进那个会话，人发起时落在看板上；发起人确认后作业才结算。
7. **版本不兼容是唯一策略。** 定义只有当前版本（v7）有效；打开存储时不做任何转换。旧版本的工作流标记「待升级」、不能启动作业；旧版本的作业标记「旧版本」、不能打开。升级 = 由编排者在当前格式下重写一份新版本；`definition/upgrade.ts` 及其测试全部删除。

## 后果

- 引擎新增：按动作提交人任务、渲染并校验创建、结束任务的投递与确认、交回方式与助理代收。
- 工具：`buka_task_create` 收 `content`；`buka_task_targets` 返回任务的 content schema；新增 `buka_task_actions`；`buka_task_complete` 只收文本与附件（人任务可带动作与表单）。
- 页面：人任务抽屉变成「选动作 → 填该动作的表单 → 提交」；作业概览只显示作业输入与最终报告；工作流 / 作业列表各多一个标签。
- 存储：任务记录的 `payload` 改为 `content`，结果去掉 `output`；旧记录保留但按旧版本处理。
- 旧工作流不会自动升级；编排者要重写一次。
