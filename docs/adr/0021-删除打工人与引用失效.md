# ADR 0021：删除打工人是硬删，引用缺失表现为不可用

- 状态：已采纳（2026-11-16）
- 影响面：Workers 的删除路由、登记表、目录与工作区注册；Workflows 的启动校验、任务派发、工作流与作业的派生状态、页面展示

## 背景

删除打工人只移除登记条目，工作流定义里的引用会静默断链，直到下一次启动作业才以「执行者未登记」失败。

另一种做法是「删除前检查引用：被工作流引用就不许删，只被历史作业用过则停用归档」。但归档会引入一个既不能干活、又留在列表里的中间状态，而「被某个工作流引用」几乎是常态，删除会被无期限地挡住。

## 决定

1. **删除是硬删**：登记条目与打工人目录一起删除，不引入归档或禁用状态。
2. **唯一阻塞条件是运行中的作业**：存在 `running` 且钉住定义里出现该标识符的作业（岗位执行者、任务类型助理或交付助理）时禁止删除；删除确认弹窗列出这些作业并提示先主动终止。已结束的作业不阻塞。
3. **工作流引用不阻塞删除**：引用了缺失标识符的工作流进入派生的「不可用」状态——不能启动作业，列表与详情标出缺哪个执行者，重新绑定后自动恢复；不落盘状态字段。
4. **作业同样派生不可用**：缺失执行者的任务派发失败并写明原因、可重试，其它分支继续跑，作业页标注。
5. **保存新定义时校验执行者与助理标识符存在**；读取既有定义不校验，只标不可用。
6. **历史展示**：已删打工人的岗位与承办者显示占位头像与「已删除」，不保留墓碑记录。
7. **删除事务**：校验目录在打工人根目录下 → 目录原子改名为同级回收名 → 删工作区注册行 → 删登记条目 → 尽力删回收目录；任一步失败回滚目录改名。已挂载但工作区注册服务不可用时拒绝删除。
8. **内建 clock 与 `driver: robot` 的条目不可删**（现状不变）。

## 后果

- 删除前能看到影响面，但删除本身不再被工作流阻塞。
- 工作流与作业多出一种派生状态「不可用」，与「停用」区分：停用是人为收起，不可用是引用断了。
- 历史作业不丢数据，但不再能解析已删执行者。
- 删除是破坏性的：目录里的 AGENTS.md 与项目 skills 会随目录一起消失，确认弹窗必须写清。
