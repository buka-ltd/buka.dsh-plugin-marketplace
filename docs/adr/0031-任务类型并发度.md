# ADR 0031：任务类型并发度取代岗位串行

- 状态：已采纳（2026-11-24）
- 影响面：workflows 的调度、定义格式与校验、任务类型编辑界面、内建机器人职责说明、中英 DETAIL；ADR 0007 第 7 条「并发由执行者实例决定」由本条替换。

## 背景

调度把一个岗位当作互斥资源：同一作业内该岗位只要有一条任务在跑，其它就绪任务全部排队，作者无法改变。这条规则把岗位当成了运行开关，但岗位只是定义的书写载体（点名执行者、承载任务类型、作为通道端点与看板行）；真正决定「这类任务能不能同时做」的是任务类型。

实际编排里，同一执行者的不同任务类型常常互不干扰（用例影响分析与部署测试），而同一任务类型有时又必须互斥（多张修复单改同一分支）。只有一个全局的岗位串行，两边都表达不了。

## 决定

1. **并发度属于任务类型，是唯一的并发维度。** 任务类型声明「同一作业内这类任务最多同时进行几条」，默认 1（一次一条），取值为正整数，省略等同于 1。
2. **计数口径是作业内、按任务类型。** 就绪任务按创建顺序（FIFO）拿名额；跨作业互不影响；预算 `maxTasks` 不变。
3. **适用于智能体与机器人任务类型。** 人任务不占引擎的并发额度：人任务要么停在待认领等人处理，要么由助理代办，而助理是代理人不是执行者，仍按助理串行。结束任务由发起人或交付助理单人处理，天然单条。
4. **取消岗位串行。** 同一岗位的不同任务类型各自有并发度，因此默认可以同时进行；要「整岗位一次一条」的作者只能把该岗位每个任务类型都设为 1，但那不构成岗位级互斥。
5. **机器人任务类型同样默认 1。** 机器人程序此前完全不受门，同类型机器人任务可以无限并发；统一后受同一个字段约束。
6. **岗位回到书写载体的角色。** 调度只看任务类型、通道与执行者，不读岗位本身。
7. **并行的工作目录风险由作者承担。** 同一智能体执行者的多个任务可能同时改同一目录；当某岗位的智能体执行者可能并行（其任务类型并发度之和大于 1），且存在没有开启工作树隔离的任务类型时，保存定义给出提示但不拦截。
8. **不做「排队中的同类任务合并」。** 合并与显式依赖、结果归属、附件可见性都冲突，暂按伪需求否决。

## 备选与否决理由

- **岗位级并发度**：无法表达「同岗位的不同任务类型分别配置」，正是本次要解决的问题。
- **两级配置（岗位默认 + 任务类型覆盖）**：岗位不是运行语义，只保留一级。
- **`queue | parallel` 布尔开关**：表达不了「最多同时几条」，无限制的「并行」又会带来资源与成本问题。因此改用正整数并发度，1 即串行。

## 后果

- 既有工作流的调度行为变化：同一岗位的不同任务类型默认并行；同一类型的机器人任务默认串行。
- 定义格式新增可选字段，不升版本，旧定义按默认 1 解释：需要补类型、校验与报错路径、客户端任务类型表单、中英文案与中英 DETAIL。
- 内建机器人的职责说明补上并发度建议（clock：建议 10），供作者挑选执行者时参考。
- 定义校验结果需要多一类「提示」：与错误一样带定位路径，但保存不被拦下。
