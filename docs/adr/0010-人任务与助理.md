# ADR 0010：人任务与助理

- 状态：已采纳（2026-11-12）
- 影响面：workflows 的人任务、robots 的 assistant 标记、页面与工具

## 背景

旧模型的 `user` 节点必须前台运行并绑定创建者活跃 turn，作业无法异步推进；引入「等待人工」状态又会让人任务变成特殊对象。

## 决定

1. **人任务就是任务。** 人岗位产出的任务；没有「等待人工」状态；所有任务都在看板上。
2. **执行者与承办者分开。** 人任务的执行者是人；承办者可以是助理机器人，也可以是本人。
3. **助理是 robot。** 助理 = 带 `assistant: true` 标记的 agent 型机器人；人任务类型声明 `assistant: "<机器人名>" | null`。
4. **有助理时自动承办。** 任务 `ready` 后引擎启动该助理的会话（一条任务一条会话），助理用自己的 skill 与人沟通，最后提交结构化结果；只有被点名的助理能认领。
5. **无助理时人直接处理。** 任务停在「待认领」，人在看板认领、按 output schema 填表提交。
6. **失败与兜底。** 助理失败后任务回到「待认领」，不自动换助理；人始终可以兜底完成。v1 不做「重新指派助理」。

## 后果

- 旧的 `session` / `delegate` / `bridge` handler 枚举删除；沟通方式是助理自己的能力。
- robots 页面要能标记 / 筛选助理；助理会话只读取和完成被指派的那条人任务。
- 人任务不占机器人实例；助理机器人 v1 同时处理一条人任务。
