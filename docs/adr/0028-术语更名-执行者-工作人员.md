# ADR 0028：术语更名为「执行者 / 工作人员」，统称用「主体」

- 状态：已采纳（2026-11-18）
- 影响面：全部中文文案、文档、代码注释与测试断言；`plugins/workflows`、`plugins/skills`、`packages/plugin-ui`、市场索引。不改代码标识符、英文文案、路由、包名与存储路径，无数据迁移。

## 背景

ADR 0014 把非人主体的总称定为「打工人」（worker）。这个词口语色彩重，在插件说明、页面标题与错误提示里偏随意；同时词表里的「执行者」原本指「岗位声明的主体」，范围包含人、智能体与机器人，两个词的含义叠在一起。代码里的 `executor` 也只分 `kind: "worker"` 与 `kind: "human"` 两种，中文却只有一个「执行者」可用，说不清「这个岗位派给的是人还是智能体 / 机器人」。

## 决定

1. **「打工人」改称「执行者」（worker）**：仍专指非人主体，可以是智能体（DSH 会话）或机器人（固定程序）；代码里 `driver` 取 `agent` / `robot`。
2. **岗位上以人的身份承担任务的主体改称「工作人员」**：代码里 `executor.kind` 取 `human`；开始 / 结束任务里的发起人若是人，就是工作人员。
3. **统称改用「主体」**：岗位声明的叫「岗位主体」，任务创建时钉住的叫「任务主体」；「主体」只有两种：工作人员与执行者。中文不再用「执行者」指 `executor`。
4. **中文文案、文档、注释与测试断言全部改用新词**；英文文案继续用 worker / human / executor，代码标识符 `worker`、`executor.kind: "worker"`、路由 `/buka-workers/*`、包名、缓存目录与登记表字段一律不变。
5. **历史 ADR 保留原写法**，作为当时的决策记录；术语以本 ADR 与 `GLOSSARY.md` 为准，「打工人」进入废弃词表。

## 后果

- 用户可见文案统一为「执行者」，非人的语义更明确；「工作人员」把岗位上的人与执行者区分开。
- 中文的「执行者」对应代码 `worker`，不再是 `executor` 的同义词；`executor` 的中文是「主体」。写文档与注释时按这个映射选词。
- 本次只改文案与注释，不改协议与存储，已有数据与工作流定义无需迁移。
- 中英对照出现一处有意的不对称：中文「执行者」对应英文 "Worker"，中文「主体」对应英文 "Executor"；插件名与产品名继续叫 Workers。
