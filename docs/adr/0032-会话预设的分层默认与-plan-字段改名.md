# ADR 0032：会话预设的分层默认与 plan 字段改名

- 状态：已采纳（2026-11-24）
- 影响面：workflows 的定义格式与校验、引擎派发、执行者登记表、Workers 设置页、工作流页任务类型卡片、`buka_workflow_save` 工具描述、中英 DETAIL、GLOSSARY

## 背景

DSH 的「标准 / PTC」是**执行者预设**（agent preset）：新建会话时选中的一组子插件（人设与工具），决定这次会话拿到哪些能力。Workflows 的两个插件此前都把执行者会话钉死在一个插件选项 `workerPreset`（默认 `standard`）上，作者既不能按任务类型、也不能按执行者预设会话模式，只能吃这一个全局值。

任务类型上已有一个 `mode` 字段，但它只接受 `"plan"`：语义只是「以计划模式起步」，与「会话模式」无关。名字却让作者以为它能选标准 / PTC —— 一次命名事故。计划模式本身是会话内的一种状态（由 `/plan` 命令进入），与执行者预设正交，两者可以组合。

## 决定

1. **任务类型新增可选 `agentPreset`**，值为执行者预设 id。只对智能体岗位生效；开始 / 结束节点、人岗位与机器人任务类型出现即定义错误。
2. **执行者记录新增可选 `agentPreset`**，作为该执行者新会话的默认预设。机器人没有会话，字段不落盘（与 `model` 的处理一致）。
3. **优先级：任务类型 > 执行者记录 > 插件选项 `workerPreset`。** 两处都不写时行为与今天完全一致。DSH 的全局默认只在 `workerPreset` 被清空时出现，而它有默认值，所以这一层实际不可达。
4. **任务类型的值随定义快照钉住；执行者的值在派发时从登记表读**，与 `model` 一致。改执行者默认会影响运行中作业的后续任务；作业内的任务类型行为不变。
5. **只影响新建会话。** 续接沿用会话已记录的预设，不重新挂载。
6. **助理会话按助理执行者自己的默认**；任务类型的 `agentPreset` 不参与（助理跑的是人岗位的任务类型）。
7. **覆盖范围只到工作流作业创建的会话。** 人在侧边栏手工开的会话不受影响：DSH 的默认预设是全局的，没有按工作区接口。
8. **保存时校验预设 id 存在。** 工作流定义报带定位路径的错误（沿用 `positions.<岗位id>.taskTypes.<类型id>.<字段>` 的形式）；执行者保存返回专用错误码。存在但激活失败（broken）的预设接受，派发时挂载失败按任务失败并给出原因。
9. **`mode` 改名为 `plan`（布尔），不兼容。** 不保留别名、不做迁移、不升版本：旧定义重新保存时因未知字段报错，按提示改成 `plan: true`；存量定义启动时不重新校验，其中的计划节点会静默按普通节点执行。

## 备选与否决理由

- **v8 内保留 `mode` 别名**：两种写法会长期并存，工具描述、校验、卡片都要解释「旧名」，而这正是一次命名事故的产物。
- **升 v9 并迁移**：仓库没有 v8→v9 迁移，不写迁移会让存量定义连读都读不出来（`buka_workflow_get` 也拿不到），只能整份重写；写迁移又违背「不兼容」。
- **按工作区设置默认预设**：DSH 的默认预设是全局 `selectedDefault`，没有按工作区的默认，本插件只能控制自己创建的会话。
- **建单时钉住执行者预设**：与 `model` 的读取方式不一致，会引入第二套快照规则；任务记录本来就只钉 `assignee` 的 id / driver / avatar。
- **用「任务提示词以 `/plan` 开头」取代字段**：`/plan` 是命令，只由交互端在消息成型前执行；消息正文里的 `/plan` 只会成为普通文本。消息里的 `/name` 手势只解析 skill，而 `plan` 不是 skill。

## 后果

- 存量工作流若用了 `mode: "plan"`，下次保存或修改前必须改成 `plan: true`；未改的作业仍能启动，但计划节点退化成普通节点。
- 执行者登记表仍是 version 4：新字段可选，读不到按未设置处理，不升版本。
- 工作流页的任务类型卡片显示预设标签；Workers 详情 Settings 增加预设选择（含「跟随工作流默认」），broken 预设标灰，`agentPresets` 服务不可用时禁用并提示。
- 中英 DETAIL、`buka_workflow_save` 的工具描述、定义校验与中英 locale 文案都要同步。
