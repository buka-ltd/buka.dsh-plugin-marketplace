# ADR 0020：打工人用不可变标识符引用，名称只作展示

- 状态：已采纳（2026-11-16）
- 影响面：Workers 的登记表、目录布局、创建与改名流程、`buka_worker_build`；Workflows 的定义格式、迁移、执行者解析、选择器与作业快照；不改机器人的输入输出契约

## 背景

现在 `name` 同时承担三件事：身份、目录名、引用键。工作流定义（`positions[].executor.name`、任务类型的 `assistant`）与作业快照存的都是名字；改名要移动目录、重建工作区，还会让所有引用断链。于是「改名」与「删除」在引用层面无法区分——两者都只是「这个名字查不到了」。

## 决定

1. **新增不可变标识符**`id`：打工人唯一的引用键，创建时由创建者主动指定，创建后不可修改。
2. **新标识符的字符集**收紧为 `^[a-z][a-z0-9_-]{0,63}$`；老记录迁移时 `id = 当前 name`，不受这条约束（新严老宽）。
3. **`name` 变为可选展示名**：可以随时改、不要求唯一；为空时显示标识符。列表、选择器与详情同时展示标识符，用于消歧。
4. **目录按标识符命名**；改名只改 `name`，不移动目录、不重建工作区。
5. **工作流定义升一个格式版本**，执行者与助理从存 `name` 改存标识符。老定义迁移时值不变（老记录的标识符就是它当前的名字），等于字段改名；查不到对应打工人的定义保持原样，读取时标不可用，迁移不报错。
6. **作业快照不迁移**：已建作业按快照里的旧字段兜底显示，登记表里查不到时显示占位头像与「已删除」。
7. **内建 clock 的标识符固定为 `clock`。**

## 后果

- 改名不再破坏任何引用，也不再移动用户目录、不再重建工作区。
- 删除与改名可以在引用层面区分：改名仍能解析，删除才是缺失。
- 定义格式升版需要迁移与兼容读取；旧作业快照永久保留旧字段。
- 选择器与详情多一处「名称 + 标识符」的消歧展示；`buka_worker_build` 的参数变成标识符必填、`name` 可选。
