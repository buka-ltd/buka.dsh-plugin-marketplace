# ADR 0006：工作流是持久资产，作业是它的运行容器

- 状态：已采纳（2026-11-12）
- 影响面：workflows 插件的定义、存储、页面、迁移；旧运行目录

## 背景

旧模型每次运行由编排 agent 现场生成一次性定义，模板只是只读参考；运行记录只是观测数据，格式升级时整目录删除。工作流无法沉淀，作业无法管理，用户资产也无法长期保存。

## 决定

1. **工作流是持久定义，可多版本。** 由编排 preset 起草并通过 `buka_workflow_save` 保存为版本；页面审阅、激活、停用；本版没有可视化编辑器。
2. **作业 = 一个工作流 + 一个输入。** 作业钉住创建时的工作流版本快照；每个作业一块看板；编号在所属工作流内递增；**不存在跨工作流的作业**。
3. **硬切换。** 首次启动删除旧 `runs/` 与模板数据，不迁移旧运行记录。
4. **用户资产进 `ctx.storageDomain`。** 工作流、作业、任务、执行记录、附件元数据进 domain 表；大文本与附件文件进插件作业目录；以后只做 domain version 迁移，不再按格式版本清空。
5. **机器人登记保留。** 只补 `driver` / `assistant` 字段，机器人目录、AGENTS.md、skills 不动。

## 后果

- 旧的「一次性、无兼容包袱」只对旧运行记录成立，不再适用于作业 / 任务。
- 页面从观测点变成控制面；插件 README、market 文案、DETAIL 长文、测试需要整体重写。
- 需要一个一次性迁移：删旧运行目录、清模板、补机器人登记字段。
