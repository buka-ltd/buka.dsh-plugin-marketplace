# ADR 0023：失败作业的两种重启

- 状态：已采纳（2026-11-17）
- 影响面：Workflows 的状态机、调度、作业记录、路由与页面

## 背景

ADR 0022 让代办失败直接失败整个作业。失败是终态，已完成的其它分支结果还在看板上，人却没有任何继续的路径；重新建作业又要把作业输入重填一遍。

失败的作业通常只差一条任务：修好问题后，想接着已完成的八条继续跑；但如果失败暴露出流程本身写错了，也会想推倒重来。

## 决定

1. **只有 `failed` 作业能重启。** `completed` 与 `cancelled` 不给入口；取消是明确放弃。
2. **从失败位置：同一个作业就地恢复。** 作业 `failed → running`；失败的任务回到 `ready`，因作业终止被取消或阻塞的任务回到 `pending` 重新按依赖就绪；人主动取消的任务保持取消，已完成的任务不动。预算计时起点重置为重启时刻，作业记录重启次数。
3. **从头开始：按原作业输入新建一个作业。** 定义用工作流当前启用的版本，原作业留在 `failed` 作为现场；新作业记录来源作业 id，发起人是点重启的人；交回方式沿用原作业，原本交回发起人的改为交回新发起人。工作流已停用时不能从头开始。
4. **没有失败任务的失败作业只提供「从头开始」。** 例如所有分支都被取消、或结束任务交付失败。
5. **状态机补三条：** 作业 `failed → running`；任务 `blocked → pending`、引擎取消的 `cancelled → pending`。人主动取消的任务不在此列。

## 后果

- 重启是人的显式动作，不是自动重试；代办再次失败仍然直接失败作业，可以再次重启。
- 「从头开始」产生第二个作业，两个作业各自有预算与看板，互不影响；失败现场留在原作业里可查。
- 「从失败位置」用的是作业钉住的定义版本，「从头开始」用的是当前启用版本——前者继续同一件事，后者按改过的流程重来。
