# @buka/dsh-plugin-workflows

持久工作流 + 作业看板。

- **工作流**是一张持久的**岗位图**：岗位、任务类型、通道、内建开始 / 结束节点与预算。
- **作业** = 一个工作流版本 + 一个输入，每个作业一块**看板**；作业编号在所属工作流内递增，不存在跨工作流的作业。
- **任务**是最小工作单元，由执行中的岗位随时添加，只能沿图上的通道派发；除启动任务外，每个任务记录自己走过的通道；依赖显式声明，任务条件满足就尽早开始。
- **结构控制风险**（没有通道就不能派发），**看板控制吞吐**（不同岗位并行，任务就绪即认领）。

## 模型速览

| 概念        | 含义                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| 工作流      | 持久定义，可多版本；编排 preset 起草保存后即可用，页面审阅 / 停用 / 重新启用                                              |
| 岗位        | 图里的节点（除开始 / 结束）；一种执行者：人或打工人（agent / robot）；只有名字和可选备注                                  |
| 任务类型    | 岗位声明的契约：任务类型的定义（预设信息）、任务内容 schema、人任务的动作、机器人完成后的创建、可选助理、可选 plan 模式   |
| 任务内容    | 创建者给这一张任务写的内容（字符串或对象），按任务类型的 content schema 校验                                              |
| 动作        | 人任务上的按钮：名称 + 可选表单 + 一组创建声明；一个动作可建多个任务，也可以不建                                          |
| 通道        | 具名的派发路线（`id` + `label`），可带任务类型白名单；同一对节点可多条、类型可重叠；回向通道必须显式标注；引擎不读 label  |
| 开始 / 结束 | 内建节点，执行者是发起人；开始节点的 content 是作业输入，next 是初始任务；结束节点的 content 是最终报告，发起人确认后结算 |
| 作业        | 一个工作流 + 一个输入；钉住版本，一块看板                                                                                 |
| 任务        | 看板上的卡；`pending / ready / running / completed / failed / blocked / cancelled`                                        |
| 依赖        | 任务声明的等待条件，指向已经创建的任务；任务依赖图无环，工作流图可以成环                                                  |

## 使用

1. 新建「工作流编排」preset 的会话，让编排 agent 起草岗位图，用 `buka_workflow_save` 保存为版本。
2. 在侧边栏「工作流」里查看定义图与契约；暂时不用时在页头停用，需要时重新启用。
3. 新建作业：
   - 页面：填作业输入，并选择最终报告交回自己还是交给助理，发起人 = 人；
   - 会话：执行 `/job` 或用 `buka_job_start` 给出作业输入，发起人 = 当前会话。
4. 看板上打工人岗位自动认领就绪任务；人任务由点名的助理承办，或由人认领并点动作。任务沿通道创建后续任务，结束任务把最终报告交回发起人，发起人确认后作业结算。

## 工具与命令

| 名称                                       | 面向                | 作用                                                |
| ------------------------------------------ | ------------------- | --------------------------------------------------- |
| `/job`                                     | 普通会话            | 列可用工作流，或按输入启动作业（发起人 = 当前会话） |
| `buka_workflow_save`                       | 编排 preset 根会话  | 校验并保存工作流新版本（保存后即可用）              |
| `buka_workflow_list` / `buka_workflow_get` | 编排 preset / 页面  | 读工作流目录 / 全文                                 |
| `buka_job_start`                           | `/job` / 页面       | 创建作业（作业输入 + 交回方式）                     |
| `buka_job_status` / `buka_job_cancel`      | 发起人 / 页面       | 读作业 / 取消作业                                   |
| `buka_task_targets`                        | 执行中的任务        | 列出当前可创建的任务目标（含任务内容 schema）       |
| `buka_task_actions`                        | 执行中的任务        | 列出人任务可点的动作与表单 schema                   |
| `buka_task_create`                         | 执行中的任务        | 按目标创建下游任务，可多次；通道由引擎解析          |
| `buka_task_complete`                       | 执行中的任务 / 助理 | 提交结果文本与附件；人任务可带动作与表单            |
| `buka_job_board` / `buka_task_get`         | 执行中的任务 / 助理 | 只读作业看板、任务与依赖结果                        |
| `buka_job_attachments`                     | 执行中的任务 / 助理 | 按可见范围检索 / 读取附件                           |

编辑工具只对 `orchestratorPresets` 点名的 preset 根会话、以及 `orchestratorWorkspaces` 点名目录里的会话可见；执行工具只对任务会话、助理会话与发起人会话可见。人任务没有模型回答工具。

## 人任务与助理

- 人任务就是普通任务，没有「等待人工」状态，全部显示在看板上。
- 人任务类型点名一个 `assistant`（`assistant: true` 的智能体）或 `null`：
  - 点名助理：任务就绪后引擎启动该助理的会话；助理拿到整张任务卡片，与人沟通后代人点动作完成。
  - `null`：任务停在待认领，人在看板认领、点一个动作（有表单的填完）提交，或只提交结果不创建任务。
- 助理失败后任务回到待认领，不自动换助理；人始终可以兜底完成。

## 附件

每个作业一个附件库。附件必须记录来源任务 / 岗位、创建者、大小、mime、sha256 与描述；可见性按数据流：产出任务、传递依赖它的任务、发起人与作业页面。不相关分支不能列出、检索或读取。文件在插件作业目录，元数据在 `ctx.storageDomain`。

## 页面

侧边栏「工作流」：工作流列表 → 工作流（**作业**（默认）/ **结构图**）→ 作业（**概览**（默认）/ **实时流程** / **看板** / **资产**）。

- 结构图是从上到下的分层图；点节点 / 通道在右侧抽屉看细节。抽屉头部是节点身份，契约字段收成紧凑标签，结构摘要与预算在顶部，完整契约按需展开。
- 实时流程把任务状态叠在定义图上；看板按岗位 × 状态展示；资产视图展示资产池，最终交付物同时出现在概览。
- 任务抽屉先给结果与可执行的操作，再给任务内容、依赖与附件；人任务先选动作、再填这个动作的表单；执行记录、类型与时间收进「更多信息」，结束交付失败时提供「重试交付」。
- 旧版本定义的工作流带「待升级」标签、不能启动作业；旧版本作业带「旧版本」标签、不能点开。

## 依赖与存储

- 需要 `@buka/dsh-plugin-workers` 提供打工人登记与任务会话。
- 需要 DSH 组合里的 `ctx.storageDomain`（base 组合自带）；工作流 / 作业 / 任务 / 执行记录 / 附件元数据在 `buka_workflow` 域，大文本与附件文件在 `~/.cache/dsh-plugin-workflows/jobs/<jobId>/`。
- 定义格式只有当前版本（v7）有效，打开存储时不做任何转换。旧版本定义的工作流保留在列表里并标记「待升级」，不能再启动作业；升级 = 由编排者在当前格式下重写一份新版本。

## 配置

配置项以 `src/options.ts` 为准：数据目录、编排 preset 名单、按工作区放行的目录、打工人 preset、并发与预算等。默认 `orchestratorPresets` 是随包发布的 `workflow-orchestrator`；`orchestratorWorkspaces` 默认为空，填了以后这些目录（含子目录）里的会话不用切 preset 也能保存 / 读取定义，适合插件自己的开发者工作区。

## 结构

- `src/domain/**`：类型、状态机、id。
- `src/store/**`：storageDomain 表、per-job 串行队列、作业目录。
- `src/definition/**`：工作流 v7 校验与任务内容模板。
- `src/engine/**`：调度、执行器、结算、恢复。
- `src/tools/**`、`src/commands/**`：模型工具与 `/job` 命令。
- `src/routes/**`：页面读取与操作路由。
- `src/client/**`：侧边栏页面。
- `lib/index.js`、`lib/client.js`：构建产物，提交进 git，不手改。
