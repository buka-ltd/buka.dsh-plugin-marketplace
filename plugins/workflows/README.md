# @buka/dsh-plugin-workflows

持久工作流 + 作业看板。

- **工作流**是一张持久的**岗位图**：岗位、任务类型、边、内建开始 / 结束节点与预算。
- **作业** = 一个工作流版本 + 一个输入，每个作业一块**看板**；作业编号在所属工作流内递增，不存在跨工作流的作业。
- **任务**是最小工作单元，由执行中的岗位随时添加，只能沿图上的边派发给直接后继；依赖显式声明，任务条件满足就尽早开始。
- **结构控制风险**（没有边就不能派发），**看板控制吞吐**（不同岗位并行，任务就绪即认领）。

## 模型速览

| 概念        | 含义                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 工作流      | 持久定义，可多版本；编排 preset 起草保存，页面审阅 / 激活 / 停用                                |
| 岗位        | 图里的节点（除开始 / 结束）；一种执行者：人或机器人（agent / program）                          |
| 任务类型    | 岗位声明的契约：payload schema、output schema、必须依赖的上游类型、人任务的助理、可选 plan 模式 |
| 边          | 允许的派发关系，可带任务类型白名单；回边必须显式标注；边上不写提示词                            |
| 开始 / 结束 | 内建节点，执行者是启动者；启动任务把原始输入转成结构化输入，结束任务携带最终交付物、投递即完成  |
| 作业        | 一个工作流 + 一个输入；钉住版本，一块看板                                                       |
| 任务        | 看板上的卡；`pending / ready / running / completed / failed / blocked / cancelled`              |
| 依赖        | 任务声明的等待条件，指向已经创建的任务；任务依赖图无环，工作流图可以成环                        |

## 使用

1. 新建「工作流编排」preset 的会话，让编排 agent 起草岗位图，用 `buka_workflow_save` 保存为版本。
2. 在侧边栏「工作流」里查看流程图与契约，激活版本。
3. 新建作业：
   - 页面：填原始输入 + 结构化输入，启动者 = 人；
   - 会话：执行 `/job`，启动者 = 当前会话；启动任务回到该会话执行。
4. 看板上机器人岗位自动认领就绪任务；人任务由点名的助理承办，或由人认领。任务沿边派发后续任务，结束任务把交付物交回启动者，作业结算。

## 工具与命令

| 名称                                       | 面向                | 作用                                                  |
| ------------------------------------------ | ------------------- | ----------------------------------------------------- |
| `/job`                                     | 普通会话            | 列已激活工作流，或按输入启动作业（启动者 = 当前会话） |
| `buka_workflow_save`                       | 编排 preset 根会话  | 校验并保存工作流新版本（草稿）                        |
| `buka_workflow_list` / `buka_workflow_get` | 编排 preset / 页面  | 读工作流目录 / 全文                                   |
| `buka_job_start`                           | `/job` / 页面       | 创建作业                                              |
| `buka_job_status` / `buka_job_cancel`      | 启动者 / 页面       | 读作业 / 取消作业                                     |
| `buka_task_create`                         | 执行中的任务        | 随时创建下游任务，可多次                              |
| `buka_task_complete`                       | 执行中的任务 / 助理 | 提交结构化结果、文本与附件                            |
| `buka_job_board` / `buka_task_get`         | 执行中的任务 / 助理 | 只读作业看板、任务与依赖结果                          |
| `buka_job_attachments`                     | 执行中的任务 / 助理 | 按可见范围检索 / 读取附件                             |

编辑工具只对 `orchestratorPresets` 点名的 preset 根会话可见；执行工具只对任务会话、助理会话与启动者会话可见。人任务没有模型回答工具。

## 人任务与助理

- 人任务就是普通任务，没有「等待人工」状态，全部显示在看板上。
- 人任务类型点名一个 `assistant`（`assistant: true` 的 agent 机器人）或 `null`：
  - 点名助理：任务就绪后引擎启动该助理的会话，助理用自己的 skills 与人沟通，最后提交结果；只有被点名的助理能认领。
  - `null`：任务停在待认领，人在看板认领、按 output schema 填表提交。
- 助理失败后任务回到待认领，不自动换助理；人始终可以兜底完成。

## 附件

每个作业一个附件库。附件必须记录来源任务 / 岗位、创建者、大小、mime、sha256 与描述；可见性按数据流：产出任务、传递依赖它的任务、启动者与作业页面。不相关分支不能列出、检索或读取。文件在插件作业目录，元数据在 `ctx.storageDomain`。

## 页面

侧边栏「工作流」：工作流列表 → 工作流详情（流程图、岗位 / 任务类型 / 边 / 开始结束契约 / 预算、作业列表）→ 作业详情（默认看板，另有流程图、任务、附件库、时间线）。任务抽屉展示 payload、依赖、执行记录、结果与附件，按 `allowedActions` 操作；人任务按 output schema 填表；结束交付失败时提供「重试交付」。

## 依赖与存储

- 需要 `@buka/dsh-plugin-robots` 提供机器人登记与任务会话。
- 需要 DSH 组合里的 `ctx.storageDomain`（base 组合自带）；工作流 / 作业 / 任务 / 执行记录 / 附件元数据在 `buka_workflow` 域，大文本与附件文件在 `~/.cache/dsh-plugin-workflows/jobs/<jobId>/`。
- 首次启动 v4 会删除旧的 `runs/` 与 `settings.json`（硬切换）；之后作业 / 任务不再按格式版本清空。

## 配置

配置项以 `src/options.ts` 为准：数据目录、编排 preset 名单、机器人 preset、并发与预算等。默认 `orchestratorPresets` 是随包发布的 `workflow-orchestrator`。

## 结构

- `src/domain/**`：类型、状态机、id。
- `src/store/**`：storageDomain 表、per-job 串行队列、作业目录。
- `src/definition/**`：工作流 v4 校验与 payload 模板。
- `src/engine/**`：调度、执行器、结算、恢复。
- `src/tools/**`、`src/commands/**`：模型工具与 `/job` 命令。
- `src/routes/**`：页面读取与操作路由。
- `src/client/**`：侧边栏页面。
- `lib/index.js`、`lib/client.js`：构建产物，提交进 git，不手改。
