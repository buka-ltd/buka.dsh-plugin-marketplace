# Buka Skills

Adds a Skills page to the sidebar with two tabs: Installed lists the skills installed globally for every DSH session, marks the ones the `skills` library manages, and can check for updates and apply them (only `update` is applied; `modified` is skipped by default, old Claude Code marketplace installs report `unsupported-source`); Saved keeps a personal list of skill sources (owner/repo, GitHub/GitLab links, any git URL, absolute local paths, and package names — packages can be saved but not expanded) entered through a Save dialog, opens a repo from its title when the source has a web address, deletes entries, probes each listable saved source as a standard npx repository or unavailable, and expands the usable ones into a cached skills tree.

Only `SKILL.md` files under the repository root `skills/` directory (any depth) count as installable; the root `SKILL.md`, agent directories such as `.claude/skills` and Claude Code marketplaces are not accepted. Every saved source is read from a local shallow clone cache (GitHub included — no API tree calls); refreshing a clone keeps the previous copy and reports a warning when it fails.

Any single skill in the tree, or every skill under a directory row (Install all), can be installed globally (via the `skills` library, original source preserved in the lock file), into a worker (the worker's `.agents/skills` and `.claude/skills`), or into a registered workspace (the workspace's `.agents/skills`) with one click. Install, uninstall and update share one serial queue, and the `ctx.bukaSkills` Host service exposes the saved repositories, their skills, and per-directory check/update so the Workers page can update a single worker or every worker in sequence.

The plugin pins `skills@1.9.0`, never spawns `npx` at runtime, and disables telemetry for both the library and its CLI.
