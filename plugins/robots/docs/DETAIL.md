# Buka Robots

Adds a Robots page to the sidebar. A robot is a directory the plugin creates under ~/.cache/dsh-plugin-robots/robots and mounts as a DSH workspace; only robots created here are managed. For each robot you can install project-level skills through npx skills, edit its AGENTS.md, open its conversation, or re-mount it after the workspace was removed. Every robot also has a preset avatar and a one-sentence responsibility statement (the read-only buka_robots tool returns it so workflows can choose the robot), and the plugin exposes the ctx.bukaRobots service (list, avatarMap, a blocking startSession and non-blocking dispatchSession / openSession with an observable handle; dispatchSession / openSession also accept an optional planMode flag that switches the session into DSH plan mode before the first prompt, and the handle can read / clear it; the service advertises supportsPlanMode; every robot session always submits a structured JSON result through the scoped structured_output tool, optionally constrained by outputSchema and, for workflow nodes, the outgoing route names, with bounded result retries and an optional abortable escape; sessions are normal runtime-root conversations under the normal approval policy). Installing the plugin also adds the robot-builder mode (an agent preset carried by its bundle patch): new sessions can pick 机器人构建, which asks what the robot should do, drafts its AGENTS.md, then creates and mounts the robot with the preset-only buka_robot_build tool. On a fresh install (an empty registry) the plugin seeds two preset robots — 软件工程师 (software engineer) and 质量保障工程师 (QA engineer) — as ordinary, editable robots.
