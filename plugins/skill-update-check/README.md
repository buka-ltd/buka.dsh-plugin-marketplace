# @buka/dsh-plugin-skill-update-check

在当前工作区检查项目技能是否有上游更新：有更新时，在新建会话输入框的**下方**、统计行最右侧（「上下文已用」圆环之后）显示一个 warn 色提示。点击提示弹出「SKILL 更新」弹窗：列出过期的项目技能，每一行一个「更新」，页脚一个「全部更新」。

检查与更新都走 `skills` 包自带的 CLI（与 `npx skills` 同一套实现），读取工作区根目录的 `skills-lock.json`：检查跑 `check -p`，更新跑 `update <name> -p`。插件本身声明了 `skills` 依赖，装插件时会一起装好，不需要另外安装 Skills 插件。

## 安装后看到什么

- 新建会话时，输入框下方的统计行最右侧（「上下文已用」圆环之后）出现 `N 个技能可更新`（英文界面是 `N skill updates`），颜色是 DSH 主题里的 `--dsw-alias-state-warn-primary`。
- 鼠标悬停显示前几个 skill 名与「点击查看并更新」。
- 点击提示直接打开弹窗并复用已有检查结果，不会重新进入加载；弹窗逐行列出过期技能（每行是技能名 + `skills-lock.json` 里记录的来源仓库），点一行右侧的「更新」只更新它，点页脚的「全部更新」更新列出的全部。更新中禁用更新按钮与「重新检查」，但不拦关闭。
- 更新结束后弹窗直接用 Host 返回的新快照刷新列表，提示计数同步变化；全部更新完时显示「项目技能都已是最新的」，提示随之消失。只有检查结论确实是「全部最新」才这么说；没有可检查对象时显示「没有可检查的项目技能」。
- 更新在后台继续：发起后可以随时关掉弹窗，输入框下方的提示条会显示「正在更新 N 个技能」；结束后短暂显示「已更新 N 个技能」，再把新快照同步到计数。重新打开弹窗也能看到进行中的状态与结果。
- 没有更新、没有项目技能、或正在首次检查时不占位置。检查失败时提示缩成一个 `!`（error 色），tooltip 给出原因；点击同样打开弹窗，可在弹窗里重新检查。
- 有本地修改的 skill 不会被更新覆盖：它不进可更新列表，弹窗只注明「有本地修改，未参与更新」。

## 检查方式

1. 浏览器只把当前会话 id 发给 Host。
2. Host 用 `sessions` 与 `workspaceRegistry` 解析当前工作区目录：优先取 `sessionIds` 包含该会话的工作区，取不到时退回会话 header 的 `cwd`，并在已注册工作区里找包含它的最长路径。
3. 读 `<工作区>/skills-lock.json`。没有这个文件，说明工作区没有由 `npx skills` 管理的项目技能，直接结束，不跑 CLI。
4. 用插件依赖里的 `skills` CLI 执行 `check -p -y`，退出码 0 / 1 都算正常结论：1 表示有更新或本地修改。
5. 只把 `↑ <name> has an update` 计入「有更新」；`✎ … has local changes` 的 skill 会被排除，避免更新覆盖本地改动。

同一个工作区在 5 分钟内只跑一次 CLI；多个会话同时挂载时共用进行中的请求。打开弹窗直接复用提示已经拿到的结果，超过 5 分钟才在后台补一次检查；只有「重新检查」传 `refresh=1` 跳过缓存。检查是只读的，不会改 lockfile、不会安装或更新任何 skill。

## 更新方式

1. 点提示打开弹窗；「更新」或「全部更新」把 skill 名（全部时省略）发给 Host。
2. Host 先强制检查一次，把请求里的名字与「确实有更新」的名字求交集，再逐个执行 `skills update <name> -p -y`；同一实例内串行，避免并发重写 lockfile。
3. 单个失败不中断整批；更新完丢弃缓存并重新检查，把新快照随响应返回。失败的 skill 留在列表里并显示原因。
4. 也可以继续用 [Skills 插件](../skills/README.md) 的页面逐项更新，两个插件用的是同一个 CLI。

更新会改写工作区的 `skills-lock.json` 与 `.agents/skills/` 下的技能目录（由 CLI 完成），没有二次确认：点了按钮就执行。

## 限制

- 只检查**项目级**技能（工作区根目录的 `skills-lock.json`）。全局技能（`~/.agents/skills`）不在这里提示，那是 Skills 插件的页面负责的范围。
- 工作区没有 `skills-lock.json` 时没有可检查的对象；手工安装、没有记录在 lock 里的技能也不参与。
- 不轮询：进入会话、切换会话时检查一次，之后在打开弹窗（结果超过 5 分钟时）或点「重新检查」时刷新。
- 首次检查要访问来源仓库，可能需要几秒到几十秒；检查期间提示不占位置。
- 提示位于 `conversation.composer.dock`（输入框卡片下方的统计行），并用 flex `order` 排在「上下文已用」圆环之后；圆环不在时仍然在统计行最右端。没有会话时不渲染；新建会话的空白会话有 id，会正常显示。
- 提示只统计「上游有更新」。只有本地修改、没有上游更新的技能不会让提示出现。

## 要求

- DSH `>= 0.2.2-rc.1`。
- 插件随包安装 `skills@1.9.0`；不需要已安装 `@buka/dsh-plugin-skills`。
- Host 需要 `sessions` 服务；`workspaceRegistry` 是可选服务，没有时退回会话的 `cwd`。

## 安全

Host 注册两条本机路由（`GET /skill-update-check/status` 与 `POST /skill-update-check/update`），并沿用 DSH web 组合的信任栅栏（`connection.requestRejection`）：非本机或未认证的请求会被拒绝。浏览器只能传会话 id、`refresh=1` 与 skill 名字，不能传路径——目录完全由 Host 从会话与工作区注册表解析；更新只接受 JSON POST，名字有长度与数量上限，并且只更新一次强制检查确认过有更新的名字。
